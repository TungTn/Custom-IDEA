# Phase 1: Repository Cleanup and Lockfile Standardization

## Overview

Purge unneeded binary files, dead test payloads, and duplicate lockfiles from the repository to reduce clone weight by ~40MB and prevent dependency drift.

## Requirements

- Functional:
  - Remove `tools/maven` from Git tracking and filesystem.
  - Remove dead test dump `resp.json` from root directory.
  - Remove orphaned `expui/toolwindows/project@20x20.svg` directory.
  - Delete duplicate `src-tauri/Cargo.lock` and preserve root `Cargo.lock`.
- Non-functional:
  - Update `.gitignore` so local test files, tools, and sub-crate lockfiles cannot be re-committed accidentally.

## Architecture

Cargo workspace resolution requires a single lockfile at the workspace root (`Cargo.lock`). Sub-crate lockfiles generated by running isolated commands inside `src-tauri` cause configuration conflicts and redundant diffs. Repository assets must only contain files active in source code or production packaging.

## Related Code Files

- Delete:
  - `tools/maven/**` (all JAR, DLL, script files)
  - `resp.json`
  - `expui/toolwindows/project@20x20.svg`
  - `src-tauri/Cargo.lock`
- Modify:
  - `.gitignore`

## Implementation Steps

1. Untrack and remove `tools/maven` from git:
   ```powershell
   git rm -r --cached tools/maven
   Remove-Item -Recurse -Force tools/maven
   ```
2. Remove dead files `resp.json` and `expui`:
   ```powershell
   git rm resp.json
   git rm -r expui
   ```
3. Remove duplicate `src-tauri/Cargo.lock`:
   ```powershell
   git rm src-tauri/Cargo.lock
   ```
4. Update `.gitignore`:
   - Add `/tools/`
   - Add `src-tauri/Cargo.lock`
   - Add `resp.json`
   - Add `expui/`
5. Run `cargo check --workspace` from root to verify that root `Cargo.lock` successfully satisfies all workspace dependencies.

## Success Criteria

- [ ] `git status` shows no untracked files in `tools/`, `expui/`, or root `resp.json`.
- [ ] `src-tauri/Cargo.lock` is removed from git tracking and ignored.
- [ ] Root `Cargo.lock` is unmodified or only reflects clean workspace resolution.
- [ ] `cargo check --workspace` passes without errors.

## Risk Assessment

- **Risk:** Existing dev script or CI expects `tools/maven/bin/mvn.cmd`.
  - **Mitigation:** Verified that `ide-run` and `useProcessRunner.ts` resolve `mvn` via system PATH, `./mvnw` wrapper, or user setting (`mavenCustomPath`). No script references `tools/maven`.
